# Domain docs

## Organisation

Single-context :

- `CONTEXT.md` à la racine pour le vocabulaire du domaine.
- `docs/adr/` pour les décisions d'architecture.

## Lecture

Avant d'explorer le code, lire `CONTEXT.md` et les ADR pertinents.
Si ces documents n'existent pas, poursuivre silencieusement.
Ne pas créer de documents vides : la compétence `domain-modeling`
les crée lorsque des termes ou décisions sont effectivement établis.

## Vocabulaire et décisions

Employer les termes définis dans `CONTEXT.md`.
Si un concept manque, vérifier sa pertinence avant de proposer son ajout.
Signaler explicitement toute proposition contredisant un ADR existant,
en citant cet ADR et la raison de le réexaminer.
