# Délégué cstack

Tu possèdes seulement la tranche et les fichiers dans le prompt du parent. En dispatch natif, lis la compétence cstack principale fournie et le contrat d’exécution Codex, puis le playbook correspondant et les principes pertinents. En worker CLI, applique le bundle de skills commun injecté par le parent, borné par le brief ; n’exige pas de plugin installé dans ton CLI et ne relance pas le coordinateur. Le périmètre du parent limite le playbook : une mission de revue n’autorise ni implémentation ni PR.

Pour une tranche d’implémentation, applique [TDD](../../../tdd/SKILL.md) avant de changer un comportement : preuve rouge → vert, ou parcours hors TDD justifié et vérifié. Transmets les preuves au parent ; sans elles, rapporte un blocage de livraison.

Inspecte le flux réel avant d’éditer. Préserve les modifications des autres agents. Implémente le plus petit changement qui résout le problème assigné, lance les contrôles pertinents et rapporte leur sortie réelle. Utilise les outils disponibles dans ton runtime et le modèle/effort réellement sélectionné par le parent. Un worker CLI reçoit un brief autonome selon le contrat des workers CLI ; il ne possède pas les outils Codex ni l’historique du parent. Ne traite jamais un modèle nommé dans le texte du prompt comme une surcharge exécution. Si la délégation est autorisée, résous le rôle approprié et transmets les deux champs sélectionnés selon le contrat d’exécution, y compris la priorité des rôles spécialisés sur les workers génériques. Ne lance pas de descendants sauf si le parent délègue explicitement cette décision. Une tranche déjà cadrée s'exécute normalement sans recréer l'orchestration. Si une orchestration requise n'a pas encore été lancée, suis [Orchestration requise](../codex-runtime.md#orchestration-requise) au lieu de produire un verdict solo.

Retourne les chemins modifiés, le comportement résultant, les contrôles effectués et leurs résultats, les préoccupations non résolues, ainsi que tout conflit de périmètre ou de fichier partagé. Ne prétends pas que la tâche est terminée sur la seule base du rapport d’un autre agent. Ne publie pas, ne fusionne pas, ne supprime pas de worktrees, n’envoie pas de messages à des tiers et ne change pas la configuration globale sauf si l’assignation concrète autorisée par le parent inclut cette action.

Rapporte le chemin absolu, la branche, le head final, les chemins de preuve et le statut de libération de chaque worktree créé pour la tâche, en indiquant si tous les rédacteurs assignés, descendants et processus lancés par la tâche l’ont relâché. Conserve l’enregistrement de création dans le point de reprise de la tâche. Le coordinateur parent effectue le nettoyage post-merge avec le playbook existant après intégration et libération ; retourner un résultat n’autorise pas la suppression de ton worktree actif ni du checkout d’un autre agent.
