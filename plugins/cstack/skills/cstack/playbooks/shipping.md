### Shipping

Follow [the Codex runtime contract](../references/codex-runtime.md).

**You own what lands. Verify each PR independently, land only the contiguous verified run from the root, and leave the rest unchanged.** Run this playbook only after the user authorizes merging, landing, shipping, or merge-when-ready.

1. **Verify every PR independently.** Use git and `gh`. Give each PR a verifier that did not write its code when native capacity permits. Run verifiers in waves if needed. Each verifier checks the parent and head on the real interface with available native tools, then returns `PASS`, `PASS+NOTES`, or `FAIL`. Models inherit by default. Use only an available `swarm workers` override from `.cstack/models.json`. CI and bot approval are inputs, not independent verdicts. Keep verdicts in `.cstack/` unless the user also authorized posting them.
2. **Find the contiguous verified run.** Walk from the lowest unmerged PR upward. Stop at the first PR without `PASS` or `PASS+NOTES`. A verified PR above that gap is not landable. Record the ceiling.
3. **Pin each verdict to the patch.** Record the verdict head SHA, base SHA, and stable `git patch-id` for the base-to-head diff. Before landing, compare the recorded patch ID with the current patch ID. Re-verify a changed patch. If only SHAs changed, preserve the code verdict but re-run mergeability and CI at the current head.
4. **Prepare only the bottom PR.** Fetch trunk. If needed, rebase the lowest verified branch onto the exact trunk tip, push it safely, and retarget only that PR with `gh pr edit <pr> --base <trunk>`. Re-run step 3 after the push. Do not retarget, arm, or merge descendants.
5. **Land one PR at a time.** If the bottom PR is mergeable, run `gh pr merge <pr> --squash`. If required checks are still running and the user authorized merge-when-ready, arm only that PR with `gh pr merge <pr> --squash --auto`. Wait for a confirmed merge before preparing the next PR.
6. **Treat `autoMergeRequest` narrowly.** It shows that GitHub auto-merge was requested for one PR. It does not prove that a descendant is queued, its verdict is current, or the stack is safe. Confirm the bottom PR's state directly.
7. **Recompute after every merge.** Fetch trunk, confirm that it contains the merged change, remove the merged PR from the frozen bottom-to-top list, and inspect the new bottom PR's base, head, checks, and patch ID. GitHub may retarget a child automatically. Verify the actual base before continuing.
8. **Watch only the current frontier.** Resolve the plugin root and run `bash <plugin-root>/scripts/run-tool.sh watch-pr/watch-pr --queued-stack --stack-prs <bottom>` as an event wake. After each wake, run `gh pr view <pr> --json state,mergedAt,mergeStateStatus,statusCheckRollup,autoMergeRequest`. Continue in the foreground until `mergedAt` is non-null or `state` is `MERGED`, then return to step 7.

   Fail when the PR closes without merging, a required check ends in `FAILURE` or `CANCELLED` and auto-merge is no longer pending, or merge state remains `UNSTABLE` or `DIRTY` with no pending auto-merge. `BLOCKED` while checks run or auto-merge is armed is not failure. Diagnose a stalled queue before changing it.
9. **Finalize the verified run.** After confirming its merges and finishing verification, run the **After a completed delivery** mode in [worktree cleanup](worktree-cleanup.md) for recorded task-created worktrees whose owners, verifiers and dependent units have released them. The coordinator preserves evidence, removes eligible paths without another confirmation, and reports any held path. Then report what merged, the next unverified PR, and the evidence needed to extend the run. Extending the ceiling requires a new verification pass.

**Reply:** State the verified run and ceiling, each verdict and verifier, what you armed, how you confirmed each merge, and what the next gap needs.
