### Refactorisation

Suivez [le contrat d’exécution Codex](../references/codex-runtime.md).

**Tu possèdes le contrat. La structure change. Le comportement ne change pas.** Distinct de Feature, qui ajoute du comportement, et Bug fix, qui le corrige.

Si le nettoyage révèle une fonctionnalité manquante ou un vrai bug, sépare-le et livre d’abord le changement structurel contre le contrat épinglé. Une reconception est permise, mais nomme-la et route vers Feature. Le travail structurel large ou transversal relève de la compétence **figure-it-out**. Ce playbook couvre le changement ciblé à moyen.

1. Épingle d’abord le contrat de comportement. Lance la compétence **how** sur le sous-système touché pour apprendre le contrat, avec sa ventilation d’explorateurs parallèles par défaut, puis écris un test de caractérisation, snapshot ou harnais d’équivalence qui capture le comportement courant avant tout déplacement de structure. Si la zone n’a pas de couverture, écris le pin avant de toucher la structure. Type check et lint ne sont pas un pin.
2. Nomme la structure qui manque au code selon [Modéliser le domaine](../references/principles/model-the-domain.md). Le code ennuyeux reste quand la forme est déjà claire et locale. La remise en forme doit supprimer des branches ou états invalides, pas ajouter de l’indirection.
3. Nomme la forme cible. Dis ce que la mise en page des modules, les types et le graphe d’appels devraient être si on les construisait aujourd’hui ([Pensée fondationnelle](../references/principles/foundational-thinking.md), [Reconcevoir depuis les premiers principes](../references/principles/redesign-from-first-principles.md)). Si la cible traverse une frontière de fonction, lance la compétence **architect** pour une exploration de conception parallèle de la forme avant le déplacement.
4. Soustrais avant d’ajouter. Supprime le code mort, collapse les wrappers à un seul appelant, retire les validateurs redondants et enlève les références orphelines avant d’introduire la nouvelle forme ([Soustraire avant d’ajouter](../references/principles/subtract-before-you-add.md)). Le plus petit changement qui atteint la forme cible part en livraison ([Protocole de paresse](../references/principles/laziness-protocol.md)). Un nettoyage spéculatif qui « pourrait aider » est rétabli.
5. Déplace par petites étapes qui préservent le comportement, chacune gardant le pin vert. Pour les remodelages d’API, migre chaque appelant et supprime l’ancienne API dans la même vague ([Migrer les appelants puis supprimer les API legacy](../references/principles/migrate-callers-then-delete-legacy-apis.md)). Ne garde pas d’anciens et nouveaux chemins parallèles. Vérifie ponctuellement chaque renommage contre les vrais fichiers. Délègue les éditions mécaniques à un sous-agent natif borné. Préserve le rôle choisi par l’appelant, y compris `simple edits` pour les petits changements bornés. Utilise `feature, refactoring` seulement quand aucun rôle n’a été sélectionné. Suis le contrat d’exécution pour l’héritage ou le modèle et l’effort configurés. Relis toi-même le diff. Quand aucun emplacement de sous-agent n’est disponible, fais les éditions dans cette session comme passe séparée au périmètre redéfini, puis relis le diff dans une seconde passe étiquetée `single-agent review`, et rapporte l’indépendance manquante. Lance `../../deslop/SKILL.md` sur le diff avant chaque commit. Garde `deslop skipped: <reason>` quand une étape ne peut vraiment pas s’exécuter.
6. Prouve que le comportement est inchangé sur l’artéfact réel, pas seulement que ça compile ([Prouver que ça fonctionne](../references/principles/prove-it-works.md)). Pour les remodelages plus larges, lance un script d’équivalence, rejoue une référence enregistrée ou smoke-test la vraie interface avec un outil natif disponible. Possède la vérification. Ne traite pas le résumé d’un délégué comme une preuve.
7. Confirme que le changement vaut la peine d’être gardé. La mesure de succès est la réduction de charge de lecture ([Réduire la charge de lecture](../references/principles/minimize-reader-load.md)). Si le diff ne baisse nulle part la charge de lecture, rétablis-le.
8. Rebase en petits commits ordonnés quand les commits sont dans le périmètre. Un commit de soustraction vient avant le remodelage et tout nettoyage de suivi. Garde chaque tranche verte. Lance **Ouvrir une PR** seulement quand l’utilisateur a autorisé la création de PR.

**Réponse :** la structure qui a changé, le pin contre lequel tu l’as tenue, la preuve d’équivalence, le delta de charge de lecture, ce qui est livré et ce qui a été rétabli. Aucun nouveau comportement. Chaque affirmation porte sa preuve ou son étiquette dans la même phrase. Mesuré, inféré ou supposition. Une prédiction ou une cause non observée est une supposition. Ne remets jamais à l’humain un contrôle que tu pourrais lancer.
