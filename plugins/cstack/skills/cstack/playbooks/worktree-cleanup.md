### Worktree and simulator cleanup

Follow [the Codex runtime contract](../references/codex-runtime.md).

**The coordinator owns cleanup.** Reuse pstack's audit, usage and preservation gates. Finishing an agent or closing a PR does not prove its worktree is disposable.

## After a completed delivery

Run this mode automatically after an authorized delivery has actually merged and its verification is complete. Safe cleanup of the temporary worktrees created for that task is part of delivery; do not ask for another confirmation. Honor an explicit request to keep them. A plan, read-only request, pause, open PR, queued merge or closed-but-unmerged PR does not trigger removal.

1. **Select only owned paths.** Read the task checkpoint's worktree inventory, recorded when each worktree was created: absolute path, branch, owning unit and agents, PR/head, and artifact locations. Match each path to `git worktree list --porcelain -z`. Do not infer ownership from a directory name, branch name, age or audit bucket. Reused and unrelated worktrees stay outside this automatic pass. An already removed and deregistered path is already complete; an unregistered directory or missing ownership record is held.
2. **Wait for release.** The owner returns its final head, checks, artifact paths and release status. The coordinator confirms that writers, verifiers, dependent units and task-started processes no longer use the worktree. Inspect native task state when available; a finished agent alone does not release its descendants, a dev server or another task. Keep locked worktrees, the primary checkout, the coordinator's active worktree, and any path with uncertain usage. Changing a shell's working directory does not release the Codex task that owns it.
3. **Prove integration of the exact current head.** Refresh the intended remote base and inspect the PR by its recorded identity. Require `MERGED` with a merge commit reachable from that base. A green check or a deleted remote branch is insufficient. Read the worktree's current `HEAD`. If it is an ancestor of the fetched base, its commits are integrated. For a squash or rebase merge where it is not an ancestor, require the current head to equal that PR's recorded merged head and the provider's head receipt; preserve the original branch ref. For a detached worktree, require a surviving local branch or tag that reaches its exact original head; otherwise keep it. A later local commit, mismatched receipt, unresolved stack dependency or unavailable merge evidence means keep the worktree. Never substitute patch similarity or a matching branch name for these checks.
4. **Preserve everything Git does not protect.** Run `git -C <path> status --porcelain=v1 --untracked-files=all --ignored` and inspect the paths. Keep tracked edits and ordinary untracked files. Ignored does not mean disposable: keep unknown files, credentials, local databases and user configuration. Task-created reproducible build/dependency outputs may be discarded only when their provenance and paths are known. Copy any task-owned `.cstack/` decisions and evidence to a surviving coordinator workspace's task directory, verify the copy, and update the checkpoint and report links before removing their original worktree. Do not overwrite another task's artifacts. If a unique artifact cannot be preserved, keep the worktree.
5. **Remove without forcing.** Immediately recheck ownership, release, branch/head, merge evidence, lock and file status after the last writer releases it. From a surviving checkout, run `git worktree remove -- <absolute-path>` for each eligible path. Preserve local and remote branch refs. If Git refuses, keep the worktree and report its reason; do not retry with `--force`, `git clean`, `reset --hard`, an unlock, or `rm -rf`. Do not run a repository-wide prune in this mode.
6. **Verify and report.** Re-list worktrees and confirm each removed path is absent, its recorded branch or recovery ref still preserves the original head, and preserved evidence is readable. Record removed and kept paths with concise reasons in the surviving checkpoint. Cleanup failure is reported separately from a successful delivery; it does not roll back a merge or prompt an automatic permission handoff.

Do not start a polling loop, new agent, scheduler or disk-wide audit just to clean up. Reuse the delivery's existing merge receipts and agent records, refreshing facts that can change. With no eligible worktree, report `cleanup: none eligible` only when relevant to the handoff.

## Requested disk cleanup

Use this broader mode only when the user requests disk reclamation or names existing worktrees to clean. It can inspect merged or abandoned worktrees and simulators beyond the current task.

1. Snapshot and audit. Record `df -h /`, then resolve the plugin root and run `bash <plugin-root>/scripts/run-tool.sh worktree-audit.sh`. The helper reads paths from `git worktree list` and classifies each worktree by size, age, merge state, uncommitted work, and PR state. It stages its locked sources under the workspace `.cstack/` directory.
2. The bucket is advice, not permission. Cross-check candidates against active native tasks when the session exposes task inspection. If active-task state is unavailable, keep uncertain worktrees.
3. Verify usage before deleting. A worktree used by an active task or subagent remains in use even when its name is absent from the sidebar. Use a bounded subagent to inspect a large available task trail when capacity permits. Never search unrelated conversations.
4. Pause on irreversible loss. `wip:N` means N tracked uncommitted edits. Show the diff and get a decision because removal loses those edits. `scratch:N` means N untracked files; name them and require deletion authority. Also inspect ignored files and preserve unique artifacts. Delete clean, merged, unused worktrees within the existing cleanup request without asking again.
5. Remove the confirmed set with `git worktree remove -- <absolute-path>`. Branch refs survive. A refusal is a reason to inspect and hold, not permission to force removal or recursively delete the directory. A separately authorized discard must name the exact path and data being lost. Confirm with `df -h /` and re-list.
6. Inspect simulators and caches only when they exist on this machine. Candidate simulator commands include `xcrun simctl --set testing delete all`, `xcrun simctl delete unavailable`, and `xcrun simctl runtime list`. Other candidates include Xcode `DerivedData`, `iOS DeviceSupport`, and package caches. Confirm exact targets and authority before deletion.

**Reply:** Removed worktrees, preserved artifact paths, and one reason for each held path. For requested disk cleanup, also report `df -h /` before and after and measured space reclaimed.
