### Autopilot-full

Follow [the Codex runtime contract](../references/codex-runtime.md).

**You own the verdicts. One owner runs each independent PR from build through merge, and no PR merges without an independent verdict.** Use this playbook when the user authorizes a queue of PRs and grants merge authority. Use `autopilot-stack.md` when the user keeps landing authority.

1. **Record scope and authority.** Mark items the operator reserves for personal review or merge. If the request asks only for a protocol or plan, return that artifact and stop. If the request already authorizes execution, continue without asking again. Record the objective, queue, done predicate, and authority in `.cstack/`.
2. **Assign one owner per PR.** Use git and `gh` only. Each bounded owner gets exclusive files and a branch. Its lifecycle includes implementation, an early pushed snapshot, an authorized ready PR, proof on the real artifact, automated-review triage from `../references/bugbot-triage.md`, prose and comment cleanup through the bundled skills, a rebase onto current trunk, `babysit.md`, and merge after step 4. Each owner writes a `decisions.tsv` trail under `.cstack/`. Do not create or publish a PR unless the user's request grants that authority.
3. **Run independent owners concurrently.** Bound concurrency to native capacity. Run extra owners in waves. Keep one writer per branch and disjoint files. Serialize overlapping work. Independent PRs branch from trunk. Dependent work starts after its parent merges. Models inherit unless `.cstack/models.json` supplies an available override for the owner's matched work.
4. **Verify every merge-ready head independently.** At the owner's reported head SHA, run as many independent verification lanes as the distinct risks require and native capacity permits. Include repository gates, a live check of the load-bearing behavior, a comparison with trunk, and a diff-and-receipts audit that distrusts the PR body. Run lanes in waves if needed. Aggregate one verdict. Send findings back to the owner. A changed head requires a fresh verdict unless the patch-ID rule in `shipping.md` preserves the code verdict.
5. **Merge only after the clean verdict.** Rebase onto current trunk before the merge-ready report. Pin the verdict to the head SHA and patch ID. After a clean verdict, the owner may squash-merge its PR with `gh` because this playbook requires explicit merge authority. Operator-reserved items stop at merge-ready. After confirmed merge and verification, the owner returns its worktree, head, evidence and release status. The coordinator runs the **After a completed delivery** mode in [worktree cleanup](worktree-cleanup.md) for completed, released units; keep worktrees needed by the next item or a verifier.
6. **Audit the program.** Continue in the foreground while the session remains active. At useful boundaries, re-read this playbook, the objective, owner trails, PR heads, checks, and merge states. Count commits, pushes, PR deltas, checks, and recorded verdicts as progress. Replace a stalled owner only after inspecting its state. Use a native scheduler only when available and requested. Do not promise that work continues after the app closes.
7. **Honor stop immediately.** On the operator's stop or hold, interrupt owners and issue a zero-writes instruction. Preserve current state under `.cstack/`.

**Reply:** Report the queue with owner, state, and head SHA; each independent verdict; merged PRs; next items; reserved operator gates; and the `.cstack/` trail paths.
